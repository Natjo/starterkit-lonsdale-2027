Composant accordion

Génère une liste de panneaux repliables accessibles. Le contenu riche est filtré par WordPress et l'ouverture peut être simple ou multiple.

Le composant fonctionne uniquement avec component('accordion', [...]) et un payload associatif.

Utilisation
component('accordion', [
    'items' => [
        [
            'title' => 'Comment se déroule une collaboration ?',
            'text' => '<p>Chaque mission commence par une phase de cadrage.</p>',
        ],
        [
            'title' => 'Quels sont les délais habituels ?',
            'text' => '<p>Un calendrier est partagé au lancement.</p>',
        ],
    ],
    'multiple' => false,
    'classes' => 'faq',
    'attributes' => ['id' => 'faq-homepage'],
]);

Les listes directes et les arguments positionnels ne sont plus supportés.

Payload
Clé Type Défaut Rôle
items list<array> [] Panneaux de l'accordéon
multiple bool false Autorise plusieurs panneaux ouverts
classes string|array '' Classes du conteneur
attributes array [] Attributs du conteneur

Chaque item utilise strictement :

Clé Type Rôle
title scalar|Stringable Texte du bouton
text scalar|Stringable Contenu riche du panneau

Un item sans titre ou sans texte valide est ignoré. Si aucun item ne reste, le composant ne produit aucun HTML.

Contrat ACF

Le layout flexible contient uniquement le repeater items :

accordion
└── items
    ├── title (text)
    └── text (wysiwyg)

multiple reste une décision du template et ne doit pas être un champ ACF :

component('accordion', array_replace($args, [
    'multiple' => false,
]));
Modes d'ouverture

Avec multiple => false :

  • le premier panneau est ouvert au chargement ;
  • ouvrir un panneau ferme les autres ;
  • le panneau actif peut être refermé.

Avec multiple => true :

  • tous les panneaux sont ouverts au chargement ;
  • chaque panneau évolue indépendamment.

Les chaînes "true" et "false" sont correctement normalisées.

Accessibilité
  • chaque déclencheur est un véritable <button> ;
  • aria-expanded reflète son état ;
  • aria-controls référence le panneau ;
  • aria-hidden reflète la visibilité du panneau ;
  • aria-labelledby donne au panneau le nom du bouton ;
  • chaque panneau utilise role="region" ;
  • les identifiants sont uniques grâce à wp_unique_id() ;
  • le titre est échappé et le contenu passe par wp_kses_post().
JavaScript

Le module components/accordion :

  • est hydraté à proximité de la zone visible ;
  • sélectionne uniquement les .details enfants directs ;
  • vérifie la relation aria-controls/id ;
  • synchronise aria-expanded et aria-hidden ;
  • nettoie ses événements avec AbortController.

L'animation repose sur le CSS et respecte prefers-reduced-motion.

Attributs protégés

Les attributs suivants sont contrôlés par le composant :

  • class ;
  • data-module ;
  • data-context ;
  • data-multiple.

Les autres attributs sûrs passent par component_attributes().

Dépendances
  • component_classes() ;
  • component_attributes() ;
  • wp_unique_id() ;
  • assets/components/accordion/accordion.js ;
  • assets/components/accordion/accordion.scss.

Version 1.0.0

    README

    Composant autocomplete

    Génère une combobox accessible avec suggestions locales et un <select> natif comme fallback. Le composant fonctionne uniquement avec component('autocomplete', [...]) et un payload associatif.

    Utilisation
    component('autocomplete', [
    'name' => 'city',
    'label' => 'Ville',
    'placeholder' => 'Saisir une ville',
    'value' => 'lyon',
    'required' => true,
    'options' => [
        ['value' => 'paris', 'label' => 'Paris', 'alt' => 'Île-de-France'],
        ['value' => 'lyon', 'label' => 'Lyon', 'alt' => 'Rhône'],
        ['value' => 'nantes', 'label' => 'Nantes', 'disabled' => true],
    ],
    'classes' => 'autocomplete-city',
    'attributes' => ['data-tracking' => 'city'],
]);

    Les arguments positionnels et les listes directes ne sont plus supportés.

    Payload
    Clé Type Défaut Rôle
    options array [] Options locales obligatoires
    name scalar|Stringable '' Nom obligatoire du <select> soumis
    label scalar|Stringable name Libellé visible
    value scalar|Stringable '' Valeur initiale
    placeholder scalar|Stringable '' Texte indicatif de la combobox
    required bool false Rend la sélection obligatoire
    classes string|array '' Classes supplémentaires
    attributes array [] Attributs supplémentaires

    Les chaînes "true", "false", "1" et "0" sont normalisées pour required.

    Options

    Une option structurée utilise strictement :

    [
    'value' => 'paris',
    'label' => 'Paris',
    'alt' => 'Île-de-France',
    'disabled' => false,
    'selected' => false,
]

    value et label sont obligatoires. L’ancien alias name du libellé n’est plus interprété. alt fournit des termes supplémentaires pour la recherche.

    Une forme associative courte reste disponible :

    'options' => [
    'paris' => 'Paris',
    'lyon' => 'Lyon',
],

    Une option désactivée reste dans le fallback natif, mais n’apparaît pas dans les suggestions. Lorsque value est vide, le premier selected => true actif devient la valeur initiale.

    Amélioration progressive

    Avant le JavaScript, le <select> reste visible, accessible et utilisable. Après hydratation, la racine reçoit is-ready, le select est masqué visuellement et la combobox prend le relais. destroy() restaure le select, son état required, son label et son focus éventuel.

    Le champ visible ne possède pas de name : seul le select est soumis. Une saisie libre sans correspondance exacte remet la valeur soumise à vide. Chaque changement réel émet input, puis change, avec propagation.

    Le champ utilise autocomplete="new-password" pour empêcher les suggestions de données personnelles du navigateur. Ce choix est volontaire : certains navigateurs ignorent autocomplete="off" pour les villes, adresses ou noms.

    Recherche et clavier

    La recherche locale examine label et alt, sans réseau, sans distinction de casse ou d’accent.

    • Flèche bas et Flèche haut parcourent les suggestions.
    • Entrée sélectionne l’option active.
    • Échap, Tab et un clic extérieur ferment la liste.
    • Le focus DOM reste dans le champ grâce à aria-activedescendant.
    • aria-selected, aria-expanded et une région aria-live exposent l’état.
    • Les collages, compositions IME et saisies mobiles passent par input.
    Cycle de vie

    Le module est hydraté à proximité du viewport. Il utilise une instance par racine, un AbortController pour les événements locaux et une écoute extérieure uniquement lorsque la liste est ouverte. Tout est nettoyé à la destruction.

    Une recherche distante nécessite un autre contrat avec annulation des requêtes et gestion des erreurs.

    Attributs protégés et dépendances

    class, data-module et data-context sont contrôlés par le composant.

    • assets/components/autocomplete/autocomplete.js ;
    • assets/components/autocomplete/autocomplete.scss ;
    • component_classes() et component_attributes().

    Composant badge

    Génère un libellé court dans un élément <span>. Le composant fonctionne uniquement avec component('badge', [...]) et un payload associatif.

    Utilisation
    component('badge', [
    'name' => 'Nouveau',
    'classes' => 'badge-highlight',
    'attributes' => [
        'aria-label' => 'Nouveau contenu',
        'data-category' => 'featured',
    ],
]);

    Les arguments positionnels, les listes directes et les anciens alias label, title et text ne sont plus supportés.

    Payload
    Clé Type Défaut Rôle
    name scalar|Stringable '' Libellé du badge
    classes string|array '' Classes supplémentaires
    attributes array [] Attributs HTML supplémentaires
    Règles de rendu
    • Aucun HTML n’est produit si name est absent, vide ou invalide.
    • Les espaces extérieurs du libellé sont supprimés.
    • Le libellé est échappé avec esc_html() : le HTML est affiché comme texte.
    • La classe badge est toujours présente.
    • Les classes sont nettoyées et dédupliquées.
    • L’attribut class est protégé et ne peut pas être remplacé.
    • Les autres attributs sûrs sont validés et échappés.
    • Aucun JavaScript n’est nécessaire.
    Exemple
    component('badge', [
    'name' => 'À la une',
    'classes' => ['badge-featured', 'text-small'],
    'attributes' => ['data-category' => 'featured'],
]);

    Produit :

    <span class="badge badge-featured text-small" data-category="featured">À la une</span>
    Dépendances
    • component_classes() pour les classes ;
    • component_attributes() pour les attributs ;
    • esc_html() pour sécuriser le libellé ;
    • assets/components/badge/badge.scss pour les styles.

    Composant btn

    Génère un <button>, un lien <a> ou un élément neutre <span> avec la classe btn. Le composant fonctionne uniquement avec component('btn', [...]) et un payload associatif.

    Le rendu PHP est partagé avec link dans template-parts/utils/action.php. Chaque composant conserve sa classe racine, sa classe SVG et ses styles.

    Variantes visuelles

    La classe btn est ajoutée automatiquement par le composant. Passer la variante souhaitée dans classes ; aucune variante visuelle n’est sélectionnée par défaut.

    classes Apparence
    btn-solid Fond plein, palette standard
    btn-solid btn-invert Fond plein adapté au contexte du fond
    btn-outline Bordure, fond transparent
    btn-ghost Sans bordure, fond transparent ; léger fond au survol 
    component('btn', ['name' => 'Découvrir', 'classes' => 'btn-solid']);
component('btn', ['name' => 'Découvrir', 'classes' => 'btn-solid btn-invert']);
component('btn', ['name' => 'En savoir plus', 'classes' => 'btn-outline']);
component('btn', ['name' => 'Annuler', 'classes' => 'btn-ghost']);

    btn-invert est un modificateur de btn-solid, pas une variante autonome. Les variantes fonctionnent avec un bouton natif, un lien ou un span et acceptent les options icon et svg décrites plus bas. Les anciens noms btn-1, btn-2 et light sont remplacés, sans alias CSS.

    Bouton
    component('btn', [
    'name' => 'Envoyer',
    'classes' => 'btn-solid',
    'attributes' => [
        'type' => 'submit',
        'aria-label' => 'Envoyer le formulaire',
    ],
]);
    Lien stylé comme un bouton
    component('btn', [
    'link' => [
        'url' => '/projet/',
        'title' => 'Découvrir le projet',
        'target' => '',
    ],
    'classes' => 'btn-solid',
    'icon' => [
        'name' => 'blank',
        'width' => 16,
        'height' => 16,
    ],
]);

    Les arguments positionnels, les listes directes, les enveloppes button/cta et la forme plate url/title ne sont plus supportés.

    Payload
    Clé Type Défaut Rôle
    name scalar|Stringable '' Libellé du bouton natif
    link array absent Données du lien url, title, target
    element 'button'|'a'|'span' selon le mode span pour un élément neutre ; sinon a avec link, button sans link
    classes string|array '' Classes supplémentaires
    svg bool|string false Affiche la flèche SVG inline du bouton à la place de icon
    icon array associatif absent Payload de component('icon', [...])
    attributes array [] Attributs HTML supplémentaires

    La présence de link sélectionne toujours le mode lien. Un link sans URL sûre ne produit aucun HTML et ne retombe pas sur name.

    Élément racine

    La présence de link génère un <a> par défaut. Sans link, le composant génère un <button> par défaut, ou un <span> avec element => 'span'.

    Exemples avec element explicite :

    // Bouton natif : <button type="button" class="btn btn-solid">…</button>
component('btn', [
    'name' => 'Ouvrir',
    'element' => 'button',
    'classes' => 'btn-solid',
]);

// Lien : <a href="/projet/" class="btn btn-solid">…</a>
component('btn', [
    'link' => [
        'url' => '/projet/',
        'title' => 'Découvrir le projet',
    ],
    'element' => 'a',
    'classes' => 'btn-solid',
]);

// Élément visuel : <span class="btn btn-solid">…</span>
component('btn', [
    'name' => 'Découvrir',
    'element' => 'span',
    'svg' => true,
    'classes' => 'btn-solid',
]);

    element ne change pas le mode choisi par la présence de link : a exige un lien valide et button s’utilise sans link. Seul span remplace la balise dans les deux modes.

    Une card dont le lien enveloppe déjà tout le contenu peut demander un élément visuel non interactif afin d'éviter d'imbriquer deux liens :

    component('btn', [
    'link' => [
        'url' => '/projet/',
        'title' => 'Découvrir le projet',
    ],
    'element' => 'span',
    'classes' => 'btn-solid',
]);

    Avec link, le span utilise link.title. Sans link, il utilise name. Il ne rend jamais href, target, rel, type, disabled ni les attributs de formulaire. Il reste volontairement non interactif et ne reçoit aucun rôle ARIA implicite.

    Toute valeur autre que span conserve la balise par défaut du mode. Un link fourni doit rester valide, même avec element => 'span'.

    Sans lien, pour un CTA visuel dans une card déjà cliquable :

    component('btn', [
    'name' => 'See',
    'element' => 'span',
    'classes' => 'btn-solid',
]);
    Bouton natif

    Le type par défaut est button. Seules les valeurs button, submit et reset sont acceptées dans attributes['type']; toute autre valeur revient à button.

    component('btn', [
    'name' => 'Indisponible',
    'attributes' => ['disabled' => true],
]);
    Lien, sécurité et état désactivé

    Les cibles _self, _blank, _parent et _top sont acceptées. Une cible _blank reçoit toujours noopener noreferrer. Un rel fourni dans attributes est conservé et fusionné.

    component('btn', [
    'link' => [
        'url' => 'https://example.com',
        'title' => 'Site externe',
        'target' => '_blank',
    ],
    'attributes' => ['rel' => 'nofollow'],
]);

    Un lien avec aria-disabled="true" est rendu sans href ni target.

    SVG intégré
    component('btn', [
    'name' => 'Découvrir',
    'svg' => true,
    'classes' => 'btn-solid',
]);

    svg affiche une flèche décorative de 24 × 24, définie directement dans le rendu partagé template-parts/utils/action.php, avec la classe .btn-svg et la couleur currentColor. Elle porte aria-hidden="true" et focusable="false". Cette option fonctionne pour les racines button, a et span. Si svg est vrai, icon est ignoré. Par défaut (false), le rendu de icon est conservé. Les booléens et leurs représentations usuelles en chaîne sont normalisés avec component_bool().

    Icône

    La classe icon-first place l’icône ou la flèche SVG avant le libellé. Sans cette classe, elle reste après. Ce réglage est purement visuel et ne modifie pas l’ordre du HTML.

    component('btn', [
    'name' => 'Découvrir',
    'icon' => ['name' => 'blank'],
    'classes' => 'btn-solid icon-first',
]);

    L’icône utilise exclusivement un payload associatif :

    'icon' => [
    'name' => 'blank',
    'width' => 16,
    'height' => 16,
]

    Une liste positionnelle comme ['blank', 16, 16] est ignorée. L’icône accompagne déjà le texte visible et reste donc décorative par défaut.

    Libellé

    Sans icon associatif ni svg actif, le libellé est rendu directement dans l’élément racine, sans span intérieur. Avec une icône ou un SVG, le libellé non vide est enveloppé dans un span. Sans texte visible, aucun span intérieur n’est rendu. Cette règle s’applique aux racines button, a et span, comme pour le composant link.

    Règles de rendu
    • Sans name, un bouton exige une icône ou un SVG et un aria-label non vide.
    • Un lien exige une URL sûre et un titre non vide, ou une icône/SVG avec aria-label.
    • Un span utilise name sans lien, ou link.title avec un lien valide.
    • Le libellé visible est échappé avec esc_html().
    • Les classes sont nettoyées et dédupliquées.
    • class, href, target, rel et type sont protégés.
    • Aucun JavaScript n’est requis.
    Icône seule

    Sans name (ou sans link.title en mode lien), une icône ou svg => true peut être rendue seule, sans span intérieur. attributes['aria-label'] est alors obligatoire et doit décrire l’action. Le label de l’icône seule ne remplace pas cet attribut sur le bouton ou le lien. Sans icône/SVG, un aria-label seul ne produit aucun HTML.

    component('btn', [
    'icon' => ['name' => 'blank', 'width' => 16, 'height' => 16],
    'classes' => 'btn-icon',
    'attributes' => ['aria-label' => 'Ouvrir les détails'],
]);

// Lien avec une icône seule.
component('btn', [
    'link' => ['url' => '/projet/'],
    'icon' => ['name' => 'blank'],
    'attributes' => ['aria-label' => 'Découvrir le projet'],
]);

    La classe btn-icon est une classe fournie par l’appelant ; elle n’active pas le mode icône seule et n’ajoute aucun style automatiquement.

    Couleurs contextuelles

    .btn-solid conserve sa palette standard. Avec la classe .btn-invert, les couleurs sont héritées du contexte : .btn-solid.btn-invert utilise --bg-action, --bg-action-text, --bg-action-hover et --bg-action-hover-text. .btn-outline utilise --bg-action pour son texte et sa bordure (currentColor). .btn-ghost utilise aussi --bg-action pour son texte et mélange cette couleur à 10 % avec du transparent pour son fond au survol. Les classes .bg-color-1, .bg-color-2 et .bg-color-3 définissent ces valeurs, y compris pour des fonds imbriqués. Aucun paramètre PHP supplémentaire n’est requis. La palette globale reste dans --color-*, le contexte de fond utilise --bg-* et le rendu du bouton utilise ses variables --btn-*.

    Variable du fond Utilisation
    --bg-action Fond de Solid Invert, texte de Outline et Ghost
    --bg-action-text Texte de Solid Invert
    --bg-action-hover Fond de Solid Invert au survol
    --bg-action-hover-text Texte de Solid Invert au survol

    Les valeurs par défaut sont définies sur :root dans variables.scss. Chaque .bg-color-* redéfinit la palette complète : un fond imbriqué retrouve ainsi ses propres couleurs, sans modifier les variables globales --color-*.

    // La couleur dépend du contexte .bg-color-* englobant.
component('btn', ['name' => 'Découvrir', 'classes' => 'btn-solid btn-invert']);

    .btn porte les règles de fond, couleur, bordure et survol. Les variantes définissent uniquement --btn-bg, --btn-color, --btn-border, --btn-hover-bg et --btn-hover-color. Ces variables sont réinitialisées sur chaque .btn pour éviter l’héritage accidentel d’un autre bouton.

    Le même survol s’applique lorsque le bouton est survolé directement ou que son parent .card est survolé. Le focus clavier reste visible avec un contour et les états disabled / aria-disabled="true" réduisent l’opacité et neutralisent les interactions à la souris.

    Dépendances
    • theme_link() pour normaliser et sécuriser les liens ;
    • component('icon', [...]) pour l’icône optionnelle ;
    • component_classes() et component_attributes() ;
    • assets/components/btn/btn.scss pour les styles.

    Les icônes de ce composant utilisent 16 × 16 par défaut. Les dimensions icon.width et icon.height explicitement fournies restent prioritaires.

    Composant date

    Affiche une date avec une valeur machine fiable. Le composant fonctionne uniquement avec component('date', [...]) et un payload associatif.

    Il utilise <time> lorsqu’un datetime valide est disponible, sinon un <span> afin de ne pas exposer une fausse sémantique.

    Utilisation
    component('date', [
    'date' => '20 juillet 2026',
    'datetime' => '2026-07-20',
    'classes' => 'date-news',
    'attributes' => ['data-tracking' => 'publication-date'],
]);

    Les arguments positionnels, les listes directes et l’ancien alias text ne sont plus supportés.

    Payload
    Clé Type Défaut Rôle
    date scalar|Stringable '' Libellé visible obligatoire
    datetime scalar|Stringable|DateTimeInterface auto Valeur machine explicite
    classes string|array '' Classes supplémentaires
    attributes array [] Attributs supplémentaires

    Si datetime est absent ou invalide, le composant tente de reconnaître une date machine dans le libellé visible.

    Formats reconnus

    La normalisation est stricte et n’utilise pas strtotime() :

    • Y-m-d, par exemple 2026-07-20 ;
    • Ymd, par exemple 20260720, format brut courant d’ACF ;
    • d/m/Y, par exemple 20/07/2026 ;
    • DateTimeInterface, converti dans le fuseau WordPress.

    Toutes les valeurs valides sont rendues au format Y-m-d. Les dates impossibles comme 2026-02-30 sont rejetées.

    component('date', [
    'date' => '20 juillet 2026',
    'datetime' => '20260720',
]);

    Produit :

    <time class="date" datetime="2026-07-20">20 juillet 2026</time>

    Sans valeur machine fiable :

    component('date', [
    'date' => '20 juillet 2026',
]);

    Produit un <span class="date">.

    Rendu et sécurité
    • Une valeur date vide ou invalide ne produit aucun HTML.
    • class et datetime sont protégés.
    • Le contenu visible autorise uniquement span, strong, em, abbr, small, sup, sub et br.
    • Les scripts, liens et balises de bloc sont supprimés.
    • Les classes sont nettoyées et dédupliquées.
    • Les attributs libres sûrs restent disponibles sur <time> ou <span>.
    • Aucun JavaScript n’est nécessaire.
    Dépendances
    • component_classes() pour les classes ;
    • component_attributes() pour les attributs ;
    • wp_kses() pour le contenu inline ;
    • wp_timezone() pour le fuseau WordPress.

    quote

    Version 1.0.0

    README

    Composant quote

    Génère une citation éditoriale avec une image, un auteur et une source facultatifs.

    Utilisation
    component('quote', [
    'quote' => '<p>Une citation éditoriale.</p>',
    'image' => $image_id,
    'author' => 'Prénom Nom',
    'source' => 'Publication',
    'url' => '/publication/',
    'classes' => 'featured',
]);

    Seule cette API est supportée. Les arguments positionnels ne sont pas acceptés.

    Payload
    Clé Type Défaut Rôle
    quote scalar|Stringable '' Citation obligatoire
    image ID|URL|Stringable null Image facultative
    image_size string|array{int,int} 'full' Taille WordPress de l’image
    author scalar|Stringable '' Nom de l’auteur
    source scalar|Stringable '' Titre de la publication ou de l’œuvre
    url scalar|Stringable '' URL facultative de la source
    classes string|array '' Classes supplémentaires du <figure>
    attributes array [] Attributs supplémentaires du <figure>

    quote est obligatoire. Une valeur vide ou complexe ne produit aucun HTML. Son HTML passe par wp_kses_post() afin de conserver le balisage éditorial autorisé.

    author et source sont toujours échappés. L’URL est filtrée avec esc_url() et n’est utilisée que si une source est présente. Une URL invalide laisse la source en texte simple.

    Structure HTML
    <figure class="quote">
    <img class="quote-image" src="..." alt="...">
    <blockquote class="quote-content"><p>Une citation.</p></blockquote>
    <figcaption class="quote-caption">
        <span class="quote-author">Prénom Nom</span>
        <cite class="quote-source">
            <a href="/publication/">Publication</a>
        </cite>
    </figcaption>
</figure>

    L’image est rendue avec component('image') et conserve son texte alternatif WordPress. Le <figcaption> est omis si l’auteur et la source sont absents. Le lien est omis si l’URL est absente ou invalide. class est réservé dans attributes, car la classe du conteneur est construite par le composant.

    Composant dialog

    Génère un déclencheur et une fenêtre modale native <dialog>. Le composant fonctionne uniquement avec component('dialog', [...]) et un payload associatif.

    Utilisation
    component('dialog', [
    'title' => 'Informations',
    'content' => '<p>Contenu de la fenêtre.</p>',
    'trigger' => [
        'type' => 'btn',
        'label' => 'En savoir plus',
        'classes' => 'btn-primary',
    ],
    'close_label' => 'Fermer',
]);

    Les arguments positionnels et les listes directes ne sont plus supportés. L’ancienne clé trigger_label et les positions numériques du déclencheur ont également été retirées.

    Payload
    Clé Type Défaut Rôle
    content scalar|Stringable '' Contenu éditorial obligatoire
    title scalar|Stringable '' Titre visible <h2>
    trigger array déclencheur bouton anglais Configuration du déclencheur
    close_label scalar|Stringable 'Close' Libellé de fermeture
    aria_label scalar|Stringable 'Dialog' Nom accessible sans titre
    id scalar|Stringable auto Identifiant du dialogue
    classes string|array '' Classes supplémentaires
    attributes array [] Attributs supplémentaires

    Le composant ne contient aucune clé de traduction. L’appelant doit transmettre les libellés déjà traduits. Passer trigger => [] retire le déclencheur généré; passer close_label => '' retire le bouton de fermeture.

    Déclencheur
    'trigger' => [
    'type' => 'link', // btn ou link
    'label' => 'Ouvrir',
    'classes' => 'dialog-link',
]

    Toute valeur de type autre que link produit un bouton. Le composant délègue le rendu à component('btn', [...]) ou component('link', [...]).

    Le déclencheur reçoit automatiquement data-dialog-id, aria-haspopup, aria-controls et aria-expanded. Un tableau vide permet de piloter le dialogue depuis un autre script.

    Nom accessible
    • Avec un title, le dialogue utilise aria-labelledby.
    • Sans titre, un aria_label explicite est prioritaire.
    • À défaut, le libellé du déclencheur est utilisé.
    • Sans aucun de ces textes, le fallback brut 'Dialog' garantit un nom.
    Rendu et sécurité
    • Un content vide ou invalide ne produit aucun HTML.
    • Le contenu est filtré avec wp_kses_post().
    • Le titre et les libellés sont échappés avec esc_html().
    • Un identifiant absent est généré avec wp_unique_id().
    • id, class, open, role, les attributs ARIA et les attributs du module sont protégés.
    Accessibilité et cycle de vie
    • showModal() fournit la modalité et la gestion native du focus.
    • Escape, le bouton de fermeture et un clic sur le backdrop ferment la fenêtre.
    • Après fermeture, le focus revient au dernier déclencheur utilisé.
    • aria-expanded reste synchronisé avec l’état du dialogue.
    • Un élément du contenu peut utiliser autofocus.
    • Les animations respectent prefers-reduced-motion.
    • Le nettoyage ferme un dialogue encore ouvert, annule les attentes d’animation et restaure le déclencheur.

    Le composant conserve le focus natif de <dialog> et n’ajoute pas de focus trap personnalisé.

    Dépendances
    • assets/components/dialog/dialog.js ;
    • assets/components/dialog/dialog.scss ;
    • component('btn', [...]) et component('link', [...]) ;
    • component_classes() et component_attributes() ;
    • wp_kses_post().

    Composant image

    Génère une balise <img> à partir d'un ID WordPress ou d'une URL. Il utilise les variantes WebP existantes et leurs dimensions mises en cache. Une liste de formats WordPress peut alimenter automatiquement srcset et l'attribut HTML sizes, sans produire de balise <picture>.

    Le composant fonctionne uniquement avec component('image', [...]) et un payload associatif.

    Utilisation
    component('image', [
    'image' => $image_id,
    'size' => 'large',
    'alt' => 'Description de l’image',
    'classes' => 'cover',
]);
    Tailles responsives
    component('image', [
    'image' => $image_id,
    'sizes' => ['718_478', 'medium'],
]);

    Le premier format disponible devient le src principal et définit les dimensions intrinsèques. Tous les formats disponibles sont triés par largeur réelle dans srcset. À partir de la largeur du format principal, le composant génère automatiquement un attribut tel que sizes="(max-width: 718px) 100vw, 718px".

    Chaque candidat utilise son WebP lorsqu'il existe, sinon son JPG/PNG. Les formats inexistants et les largeurs dupliquées sont ignorés. Il est recommandé d'utiliser des formats de même ratio, car srcset choisit une résolution et ne gère pas l'art direction.

    Une URL de la médiathèque WordPress est automatiquement reliée à son ID afin de retrouver les formats demandés :

    component('image', [
    'image' => $image_url,
    'sizes' => ['718_478', 'medium'],
]);

    Une URL externe reste acceptée, mais elle est rendue comme une source unique : WordPress ne possède pas les métadonnées nécessaires pour en déduire d'autres formats. La résolution d'une même URL vers son ID est mémorisée pendant toute la requête PHP afin d'éviter les recherches SQL répétées.

    La clé source est uniquement image. Les anciens alias src, url et les arguments positionnels ne sont plus supportés.

    Champs ACF

    Les champs ACF image retournent l'ID du média. Leur nom n'a aucune incidence : la valeur est explicitement placée dans image.

    component('image', [
    'image' => $args['image'] ?? null,
    'size' => 'large',
]);

component('image', [
    'image' => $args['photo'] ?? null,
    'size' => 'large',
]);

component('image', [
    'image' => $args['visu'] ?? null,
    'size' => 'large',
]);

    WordPress retourne la déclinaison demandée, ses dimensions et le texte alternatif de la médiathèque. Un champ vide ne produit aucun HTML.

    Payload
    Clé Type Défaut Rôle
    image ID|URL|Stringable — Source de l'image
    size string|array{int,int} full Taille WordPress
    sizes list<string> [] Formats WordPress du srcset, le premier étant la source principale
    alt scalar|Stringable alt WordPress Texte alternatif
    width int dimension détectée Largeur explicite
    height int dimension détectée Hauteur explicite
    lazy bool true Active loading="lazy"
    critical bool false Rend l'image prioritaire
    preload bool false Précharge et rend l'image prioritaire
    decoding async|sync|auto async Stratégie de décodage
    fetchpriority low|auto|high — Priorité réseau
    classes string|array '' Classes supplémentaires
    attributes array [] Attributs HTML supplémentaires

    Une valeur alt => '' explicite déclare une image décorative. Sans clé alt, le texte alternatif WordPress est utilisé. Pour une URL distante, width et height permettent d'éviter un décalage de mise en page.

    Chargement
    Configuration loading fetchpriority Preload
    défaut lazy absent non
    lazy => false absent absent non
    critical => true absent high non
    preload => true absent high oui

    fetchpriority="high" est accepté uniquement avec critical ou preload. Les chaînes "true" et "false" sont normalisées. Une image critique n'est jamais chargée en lazy.

    Sécurité
    • une source vide, introuvable ou refusée par esc_url() ne produit rien ;
    • class, src, srcset, sizes, alt, width, height, loading, decoding et fetchpriority sont réservés ;
    • les handlers on*, srcdoc et les valeurs complexes sont refusés.
    Dépendances
    • lsd_get_thumb() ;
    • lsd_image_webp_src() ;
    • lsd_image_file_dimensions() ;
    • theme_enqueue_image_preload() ;
    • component_classes() ;
    • component_attributes().

    La présence de link sélectionne le mode lien : une URL sûre et un titre non vide sont attendus, même pour un span. Un titre vide est accepté uniquement avec une icône/SVG et un aria-label non vide. Un lien invalide ne retombe pas sur name. Sans link, name fournit le libellé visible ; son absence suit les mêmes règles pour une icône seule.

    element => 'span' fonctionne dans les deux modes. Les autres valeurs conservent la racine par défaut : a avec link, button sans link. Le span ne reçoit ni href, target, rel, type, disabled, ni attributs de formulaire. Aucun rôle ARIA n’est ajouté implicitement.

    Le bouton natif accepte button, submit ou reset dans attributes.type, avec button par défaut. Il prend en charge disabled.

    Les cibles _self, _blank, _parent et _top sont acceptées. Avec _blank, noopener noreferrer est fusionné avec attributes.rel. Pour un lien avec aria-disabled="true", href et target sont retirés.

    svg => true affiche une flèche inline de 24 × 24 avec la classe .link-svg, currentColor, aria-hidden="true" et focusable="false". icon est alors ignoré. Sinon, l’icône associative est rendue via component('icon', ...).

    Sans icon associatif ni svg actif, le libellé est rendu directement dans l’élément racine, sans span intérieur. Avec une icône ou un SVG, le libellé non vide est enveloppé dans un span. Sans texte visible, aucun span intérieur n’est rendu. Cette règle s’applique aux racines a, button et span, pour link comme pour btn.

    Les libellés et attributs sont échappés à la sortie. class, href, target, rel et type sont protégés. Les payloads positionnels et la forme plate url/title sont refusés. Aucun JavaScript n’est requis.

    Icône seule

    Sans name (ou sans link.title en mode lien), une icône ou svg => true peut être rendue seule, sans span intérieur. attributes['aria-label'] est alors obligatoire et doit décrire l’action. Le label de l’icône seule ne remplace pas cet attribut sur le bouton ou le lien. Sans icône/SVG, un aria-label seul ne produit aucun HTML.

    component('link', [
    'icon' => ['name' => 'blank', 'width' => 16, 'height' => 16],
    'classes' => 'link-icon',
    'attributes' => ['aria-label' => 'Ouvrir les détails'],
]);

// Lien avec une icône seule.
component('link', [
    'link' => ['url' => '/projet/'],
    'icon' => ['name' => 'blank'],
    'attributes' => ['aria-label' => 'Découvrir le projet'],
]);

    La classe link-icon est une classe fournie par l’appelant ; elle n’active pas le mode icône seule et n’ajoute aucun style automatiquement.

    Position de l’icône

    La classe icon-first place l’icône ou la flèche SVG avant le texte. Sans cette classe, elle reste après. L’ordre du HTML reste inchangé.

    component('link', [
    'link' => ['url' => '/contact/', 'title' => 'Contact'],
    'icon' => ['name' => 'blank'],
    'classes' => 'icon-first',
]);
    Couleurs contextuelles

    Le composant définit --link-color et --link-color-hover pour sa couleur normale et sa couleur au survol. Le lien standard utilise --color-2. Les classes .bg-color-* ne définissent aucune variable propre aux liens.

    Niveau Variables Rôle
    Palette globale --color-* Couleurs de référence du site
    Contexte de fond --bg-color, --bg-text Fond et texte du contexte courant
    Composant --link-color, --link-color-hover Couleurs normale et au survol

    Avec .link-invert, --link-color reprend directement --bg-text du contexte et la couleur de survol suit cette même valeur. --bg-text est défini par défaut sur :root et redéfini par chaque .bg-color-*. Cela fonctionne aussi avec des fonds imbriqués, sans modifier --color-text ni nécessiter de sélecteur parent spécifique.

    component('link', [
    'link' => ['url' => '/contact/', 'title' => 'Contact'],
    'classes' => 'link-invert',
]);

    La classe link est ajoutée automatiquement ; link-1 n’est plus utilisée. Le soulignement apparaît au survol. Le focus clavier conserve un contour et un soulignement visibles avec currentColor.

    Dépendances

    • component('icon', [...]) pour l’icône optionnelle ;

    • assets/components/link/link.scss pour les styles.

    component('list', [

    Génère une balise <picture> à partir d'IDs de médias WordPress ou d'URLs. Il gère une variante desktop/mobile, les WebP existants, les dimensions, le lazy loading et le preload des images critiques.

    Image simple

    Les champs ACF image retournent l'ID du média :

    component('picture', [

    'size' => 'large',
    'classes' => 'editorial-image',
]);

    component('picture', [
    'images' => [
        'desktop' => $args['image_desktop'] ?? null,
        'mobile' => $args['image_mobile'] ?? null,
    ],
    'desktop_size' => 'large',
    'mobile_size' => 'medium_large',
    'breakpoint' => 768,
]);

    desktop et mobile sont acceptés uniquement dans images. Les anciennes formes positionnelles et les variantes placées à la racine ne sont plus supportées.

    Payload
    Clé Type Défaut Rôle
    image ID|URL — Source simple recommandée
    size string|array{int,int} full Taille commune
    images ID|URL|array{desktop?,mobile?} — Compatibilité simple ou variantes responsive
    desktop_size string|array{int,int} valeur de size Taille WordPress desktop
    mobile_size string|array{int,int} valeur de size Taille WordPress mobile
    cover bool false Recadre l’image pour remplir la hauteur disponible
    alt scalar|Stringable alt WordPress Texte alternatif du fallback
    classes string|array '' Classes du <picture>
    attributes array [] Attributs du <picture>
    lazy bool true Active loading="lazy"
    critical bool false Force une priorité haute
    preload bool false Précharge et rend l'image critique
    placeholder bool false Rend un <picture> vide sans image
    breakpoint int 768 Séparation desktop/mobile en pixels

    Les chaînes "true" et "false" sont normalisées. Une valeur alt => '' explicite permet de déclarer l'image décorative.

    Si image et images sont fournis ensemble, images est prioritaire. De la même manière, desktop_size et mobile_size remplacent size pour leur variante respective.

    Ajustement dans le conteneur

    Par défaut, l’image conserve ses proportions naturelles. La classe structurelle picture est toujours présente ; aucune classe fit-* n’est générée. L’ancienne option fit n’est plus interprétée.

    width: 100%;
height: auto;

    L’option cover => true ajoute la classe cover et remplit la hauteur disponible :

    width: 100%;
height: 100%;
object-fit: cover;

    Le composant ne fixe aucun ratio. La strate, la card ou le module concerné définit aspect-ratio selon son design :

    .slider-image {

}
    Chargement
    Configuration loading fetchpriority Preload
    défaut lazy absent non
    lazy => false absent absent non
    critical => true absent high non
    preload => true absent high oui, avec fetchpriority="high"

    Avec deux variantes, le preload utilise les mêmes media queries que les sources : mobile sous le breakpoint et desktop à partir du breakpoint.

    • une variante WebP existante est utilisée dans un <source> ;
    • l'original reste le fallback dans <img> ;
    • les recherches WebP et leurs dimensions conservent les caches existants ;
    • width et height sont rendus lorsqu'ils sont connus.

    Le composant ne génère volontairement aucun srcset ou sizes WordPress. Le srcset présent sur les balises <source> désigne uniquement une variante desktop, mobile ou WebP précise.

    • une source invalide ne produit aucun média.

    Interaction et API JavaScript

    Le drag suit le pointeur. Au relâchement, l’animation rejoint la page suivante ou précédente sans déplacement brutal. Un changement rapide de direction conserve la position, et les liens restent cliquables tant qu’aucun swipe réel n’a eu lieu. Les positions restent cohérentes dans un conteneur positionné (position: relative, par exemple). Le tactile et le trackpad conservent leur scroll natif ; leur relâchement ne déclenche pas l’animation du drag souris. Les clics successifs sur les flèches partent de la destination demandée, même pendant l’animation. Un relâchement hors de la piste, une annulation ou une perte de focus libère le geste ; les liens restent activables au clavier. Le scroll au tactile ou à la molette interrompt une animation en cours.

    import { Slider } from "./slider";

const slider = new Slider(element);
slider.onchange = (page, lastPage, progress) => {};
slider.onnext = (page) => {};
slider.onprev = (page) => {};
slider.add();
slider.slideTo(2);
slider.remove();

    Les index correspondent aux pages de scroll, pas nécessairement aux items. remove() débranche les listeners, observers, frames et contenus générés. slideTo() est sans effet avant add() ou après remove(). Un nouvel add() réactive l’instance. Les contrôles ne sont réécrits que lorsque la page active ou la géométrie change. prefers-reduced-motion désactive le scroll animé.

    Les dimensions et les positions sont mémorisées à la mesure, puis recalculées lorsqu’un conteneur ou une slide change de taille. Les positions sont triées et dédupliquées en un passage ; la page la plus proche est trouvée par recherche binaire. La timeline suit une seule boucle pendant l’animation et n’est réécrite que si sa progression change. Les écouteurs globaux du pointeur existent uniquement pendant un geste et sont retirés au relâchement ou à la destruction.

    • Chaque item est annoncé comme une slide avec sa position réelle.
    • Les boutons natifs sont désactivés aux limites.
    • La pagination expose la page active avec aria-current="page".
    • Les flèches clavier agissent lorsque la liste elle-même a le focus.
    • Les attributs structurels, ARIA et ceux du module sont protégés.

    'title' => 'Présentation',
    'content' => '<p>Contenu éditorial.</p>',
    'selected' => true,
    'disabled' => false,
    'tab_attributes' => ['data-track' => 'presentation'],
    'panel_attributes' => ['data-section' => 'presentation'],
]

    Les clés de contenu sont strictement title et content. Les anciens alias label et text ne sont plus interprétés. Les chaînes "true", "false", "1" et "0" sont normalisées pour selected et disabled.

    Le premier item non désactivé avec selected => true devient actif. À défaut, le premier item non désactivé est sélectionné. Un item désactivé ne peut jamais être actif. Si tous les items sont désactivés, aucun HTML n’est produit.

    Le contenu est filtré avec wp_kses_post().

    Navigation clavier

    Orientation horizontale :

    • Flèche gauche sélectionne l’onglet précédent ;
    • Flèche droite sélectionne le suivant.

    Orientation verticale :

    • Flèche haut sélectionne l’onglet précédent ;
    • Flèche bas sélectionne le suivant.

    Dans les deux orientations, Début et Fin sélectionnent le premier ou le dernier onglet actif. La navigation ignore les onglets désactivés, boucle aux extrémités et laisse Tab conserver son comportement natif.

    Accessibilité
    • Une seule tab possède aria-selected="true" et tabindex="0".
    • Chaque bouton role="tab" contrôle son panneau avec aria-controls.
    • Chaque panneau role="tabpanel" est nommé avec aria-labelledby.
    • Les panneaux masqués utilisent hidden.
    • Les panneaux reçoivent tabindex="0" pour être atteints directement.
    • Les identifiants, rôles, états ARIA, hidden, tabindex et disabled sont protégés contre les attributs personnalisés.
    Cycle de vie

    Le module components/tab est hydraté à proximité du viewport. Son nettoyage retire les événements et restaure les états HTML initiaux.

    Composant table

    Génère une table de données accessible et responsive, sans JavaScript. Le composant fonctionne uniquement avec component('table', [...]) et un payload associatif.

    Utilisation
    component('table', [
    'caption' => 'Résultats',
    'headers' => ['Nom', 'Valeur'],
    'rows' => [
        ['Alpha', '10'],
        ['Beta', '20'],
    ],
]);

    Les arguments positionnels et les listes directes ne sont plus supportés.

    Payload
    Clé Type Défaut Rôle
    headers array [] Colonnes obligatoires
    rows list<array> [] Lignes obligatoires
    id scalar|Stringable auto Base des identifiants
    caption scalar|Stringable '' Caption visible
    aria_label scalar|Stringable 'Tableau de données' Caption masquée par défaut
    row_headers bool false Transforme la première cellule en en-tête de ligne
    scrollable bool true Rend la zone de défilement focalisable
    classes string|array '' Classes du conteneur
    table_classes string|array '' Classes du <table>
    attributes array [] Attributs du conteneur
    scroll_attributes array [] Attributs de la zone de défilement
    table_attributes array [] Attributs du <table>
    caption_attributes array [] Attributs du <caption>

    Les chaînes "true", "false", "1" et "0" sont normalisées pour les options booléennes. Aucun appel de traduction n’est effectué dans le composant.

    Colonnes structurées

    Une colonne simple est une chaîne. Une colonne structurée utilise strictement la clé label :

    'headers' => [
    'name' => [
        'label' => 'Nom',
        'scope' => 'col',
        'classes' => 'column-name',
        'attributes' => ['data-column' => 'name'],
    ],
    'value' => [
        'label' => 'Valeur',
        'colspan' => 2,
    ],
],

    La clé associative (name, value) permet de lire les lignes indépendamment de l’ordre de leurs données. Les anciens alias title et name du libellé ne sont plus interprétés. scope accepte col ou colgroup; colspan et rowspan sont limités de 1 à 100.

    Lignes et cellules structurées

    Une ligne peut être séquentielle ou suivre les clés des colonnes :

    'rows' => [
    ['Alpha', '10'],
    ['value' => '20', 'name' => 'Beta'],
],

    Une cellule structurée utilise strictement content :

    [
    'content' => '<strong>Alpha</strong>',
    'header' => true,
    'scope' => 'row',
    'colspan' => 1,
    'rowspan' => 1,
    'classes' => 'is-highlighted',
    'attributes' => ['data-value' => 'alpha'],
]

    Les anciens alias value et text ne sont plus interprétés. scope accepte row ou rowgroup.

    Une ligne peut séparer ses cellules de ses attributs :

    [
    'cells' => ['name' => 'Alpha', 'value' => '10'],
    'attributes' => ['data-row' => 'alpha'],
]
    Caption et défilement

    Une balise <caption> est toujours présente. Lorsque caption est vide, aria_label est rendu dans une caption visuellement masquée.

    Avec scrollable => true, la zone reçoit tabindex="0", role="region" et aria-labelledby. Utiliser false seulement lorsqu’aucun débordement horizontal n’est possible.

    La largeur minimale peut être ajustée localement :

    'attributes' => ['style' => '--table-min-width: 48rem'],
    Normalisation et sécurité
    • Une colonne sans libellé est ignorée.
    • Une ligne non-tableau ou entièrement vide est ignorée.
    • Une cellule manquante produit une cellule vide pour préserver la grille.
    • Une cellule excédentaire sans colonne correspondante est ignorée.
    • Le HTML des en-têtes et cellules est filtré avec wp_kses_post().
    • Les identifiants et attributs structurels sont protégés.
    • Les classes sont nettoyées et dédupliquées.

    Pour des en-têtes sur plusieurs lignes ou des associations très complexes, préférer un template métier dédié.

    Dépendances
    • component_classes() et component_attributes() ;
    • wp_kses_post() pour les contenus éditoriaux ;
    • assets/components/table/table.scss pour le rendu responsive.

    Génère un titre h1 à h6. Le HTML autorisé par WordPress est conservé et la classe CSS title est toujours ajoutée.

    component('title', array_replace($args, [

    Composant tooltip

    Affiche une courte information complémentaire au survol, au focus clavier ou au toucher. Le composant fonctionne uniquement avec component('tooltip', [...]) et un payload associatif.

    Utilisation
    component('tooltip', [
    'label' => 'Délai estimé',
    'content' => 'Entre <strong>3 et 5 jours</strong>.',
    'classes' => 'tooltip-right',
    'attributes' => ['data-tracking' => 'delivery-delay'],
]);

    Les arguments positionnels et les listes directes ne sont plus supportés.

    Payload
    Clé Type Défaut Rôle
    label scalar|Stringable '' Texte visible du bouton
    content scalar|Stringable '' Explication courte non interactive
    classes string|array '' Classes supplémentaires
    attributes array [] Attributs supplémentaires du conteneur

    label et content sont obligatoires. Une valeur vide ou complexe ne produit aucun HTML. La chaîne "0" reste valide.

    Contenu autorisé

    Le contenu est filtré avec wp_kses() et accepte uniquement :

    br, strong, em, b, i, small, sup, sub, span[class]

    Les liens, boutons, médias et formulaires sont supprimés. Un contenu riche ou interactif doit utiliser un composant popover ou dialog.

    Le label est toujours échappé avec esc_html().

    Accessibilité et interactions
    • Le déclencheur est un véritable <button type="button">.
    • aria-describedby relie le bouton au contenu role="tooltip".
    • Le tooltip apparaît au survol et au focus clavier.
    • Sur écran tactile, un premier toucher ouvre et un second ferme.
    • Escape et un clic extérieur ferment le tooltip.
    • Le contenu reste survolable avec le pointeur.
    • Le positionnement horizontal est corrigé près des bords de l’écran.
    • Les animations respectent prefers-reduced-motion.

    aria-expanded n’est volontairement pas utilisé : il n’appartient pas au pattern ARIA du tooltip.

    Attributs protégés

    Le composant contrôle class, data-tooltip, data-module, data-tooltip-open et data-tooltip-dismissed. Les autres attributs sûrs sont conservés.

    Cycle de vie

    Le module components/tooltip gère ses événements et son nettoyage à la destruction du composant. Le comportement JavaScript ne dépend d’aucune option de traduction ou de contenu PHP.

    Dépendances
    • assets/components/tooltip/tooltip.scss ;
    • assets/components/tooltip/tooltip.js ;
    • component_classes() et component_attributes() ;
    • wp_kses() et esc_html().

    Composant video

    Affiche une vidéo HTML5 ou un lecteur YouTube/Vimeo. Le composant fonctionne uniquement avec component('video', [...]) et un payload associatif.

    Source unique
    component('video', [
    'url' => '/videos/presentation.mp4',
    'title' => 'Présentation du projet',
    'poster' => '/images/presentation.jpg',
]);
    Sources multiples
    component('video', [
    'sources' => [
        '/videos/presentation.webm',
        '/videos/presentation.mp4',
        ['src' => '/videos/presentation.custom', 'type' => 'video/mp4'],
    ],
    'title' => 'Présentation du projet',
]);

    Les arguments positionnels et les listes directes ne sont plus supportés. Une source structurée utilise uniquement src; l’ancien alias url n’est plus interprété dans sources.

    Payload
    Clé Type Défaut Rôle
    url scalar|Stringable '' Source unique ou ID média WordPress
    sources list<scalar|array> absent Sources HTML5 multiples
    title scalar|Stringable 'Lecteur vidéo' Nom accessible du lecteur
    poster URL|ID média '' Image de façade
    play_label scalar|Stringable 'Lire la vidéo' Libellé du bouton de façade
    autoplay bool false Lecture automatique
    lazy_autoplay bool automatique Limite l’autoplay HTML5 à la zone visible
    loop bool false Lecture en boucle
    controls bool automatique Affiche les contrôles HTML5
    preload 'none'|'metadata'|'auto' 'metadata' Préchargement HTML5
    tracks list<array> [] Sous-titres et pistes textuelles
    classes string|array '' Classes du conteneur
    attributes array [] Attributs supplémentaires

    Si sources est présent, il est prioritaire et doit être une liste. Les chaînes "true", "false", "1" et "0" sont normalisées pour les options booléennes.

    Les extensions mp4, m4v, webm, ogv, ogg et mov reçoivent leur type MIME. Un type explicite doit être l’un de ces types reconnus. Les doublons et les URL dangereuses sont ignorés.

    YouTube et Vimeo
    component('video', [
    'url' => 'https://www.youtube.com/watch?v=dQw4w9WgXcQ',
    'title' => 'Présentation vidéo',
    'poster' => $poster_id,
]);

    YouTube utilise le domaine youtube-nocookie.com. Les identifiants Vimeo et YouTube sont extraits uniquement depuis des URL reconnues. Un lecteur externe n'est jamais chargé au rendu PHP : son URL reste dans data-src jusqu'à son entrée dans le viewport ou, lorsqu'un poster existe, jusqu'à l'action de l'utilisateur.

    Façade et autoplay

    Un poster active une façade locale pour les lecteurs externes comme pour les vidéos HTML5. Le média n'est alors chargé ou démarré qu'après un clic. Le bouton possède un nom accessible composé de play_label et de title, puis transfère le focus au lecteur.

    Sans poster, aucune façade ni bouton n'est rendu. Une iframe YouTube ou Vimeo reste néanmoins différée par data-context="@visible true" et n'est chargée que lorsque le composant arrive dans le viewport.

    Sans façade, l’autoplay HTML5 est muet, utilise playsinline, démarre à l’approche de la zone visible et s’arrête hors écran. Avec prefers-reduced-motion, l’autoplay est neutralisé et les contrôles restent disponibles.

    Une façade force preload="none". L’autoplay différé fait de même afin d’éviter un téléchargement prématuré. Pour un lecteur externe avec façade, autoplay ne contourne jamais le clic obligatoire.

    Sous-titres
    'tracks' => [[
    'src' => '/videos/presentation-fr.vtt',
    'kind' => 'subtitles',
    'srclang' => 'fr',
    'label' => 'Français',
    'default' => true,
]],

    Les valeurs de kind acceptées sont subtitles, captions, descriptions, chapters et metadata. Une piste invalide est ignorée.

    Sécurité et attributs protégés
    • Seuls HTTP(S), les chemins absolus et les chemins relatifs sûrs sont acceptés.
    • Les caractères de contrôle et les antislashs sont refusés dans les URL.
    • class, data-type, data-autoplay, data-autoplay-src, data-module et data-context sont contrôlés par le composant.
    • Le poster décoratif utilise component('image', [...]).
    • L’icône de lecture utilise component('icon', [...]).

    • youtube_id_from_url() pour YouTube ;
    • component_classes() et component_attributes() ;
    • assets/components/video/video.js ;
    • assets/components/video/video.scss.
