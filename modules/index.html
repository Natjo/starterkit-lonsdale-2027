Module breakpoint

Observe le passage au-dessus ou en dessous d'une largeur avec matchMedia. Contrairement à un listener resize, il ne déclenche un callback que lorsque la media query change d'état.

Utilisation
import breakpoint, { BREAKPOINTS } from "@modules/breakpoint/breakpoint";

const destroy = breakpoint(BREAKPOINTS.md, {
    above: media => {
        // Largeur supérieure ou égale à 768px.
    },
    under: media => {
        // Largeur inférieure à 768px.
    },
});

// Lorsque le module ou le composant est détruit.
destroy();

Le callback correspondant à la largeur courante est appelé immédiatement, sans timer. Les appels suivants ont lieu uniquement lors du franchissement du breakpoint.

Chaque callback reçoit la MediaQueryList courante ou l'événement change, qui exposent tous les deux la propriété booléenne matches.

Breakpoints disponibles
Nom Valeur
xs 480px
sm 576px
md 768px
lg 1025px
xlg 1200px
wd 1440px
xwd 1920px
xlgwd 2400px

Ces valeurs doivent rester alignées avec assets/styles/_breakpoints.scss. Utiliser les constantes exportées plutôt que répéter une valeur en dur dans les modules JavaScript.

Contrat
  • value doit être un nombre fini positif ou nul ; une valeur invalide produit une fonction de nettoyage sans effet ;
  • above et under sont facultatifs ;
  • appeler plusieurs fois la fonction de nettoyage est sans effet secondaire ;
  • sans window.matchMedia, le module retourne un nettoyage vide et ne lance aucun callback ;
  • le module ne doit pas être appelé avec new.

Dans un module hydraté, retourner directement son nettoyage lorsque celui-ci est la seule ressource persistante :

export default function initExample(root) {
    return breakpoint(BREAKPOINTS.lg, {
        above: () => root.classList.add("is-desktop"),
        under: () => root.classList.remove("is-desktop"),
    });
}

Hydrate

Charge à la demande les modules JavaScript déclarés dans le HTML avec data-module, puis gère leur cycle de vie.

Son manifeste utilise "activation": { "pageType": "any" } parce que assets/app.js l’initialise globalement dès que le site possède une page. Une page ou une strate ne doit donc pas le déclarer comme dépendance uniquement pour empêcher Forge de le supprimer.

Markup
<section
    data-module="strates/strate-example"
    data-context="@visible true"
    data-module-media="(min-width: 768px)"
></section>

Les familles acceptées sont common, components, heros, pages et strates. Le fichier chargé doit porter le même nom que son dossier.

Chargement
  • sans data-context, le module est chargé immédiatement ;
  • data-context="@visible true" attend que l’élément approche du viewport ;
  • data-module-media attend que la media query corresponde ;
  • les imports résolus et en cours sont mis en cache pour éviter les chargements multiples.
Contrat d’un module
export default function initExample(root) {
    const onClick = () => {};
    root.addEventListener("click", onClick);

    return {
        pause() {},
        resume() {},
        destroy() {
            root.removeEventListener("click", onClick);
        },
    };
}

Un module peut retourner une fonction de nettoyage, un lifecycle { pause, resume, destroy }, plusieurs lifecycles dans un tableau ou undefined. Les destructions multiples sont sécurisées et les tableaux sont détruits dans l’ordre inverse.

API
  • hydrate(container) initialise les éléments [data-module] présents dans un conteneur ;
  • observe(container) surveille les ajouts et suppressions dynamiques avec un MutationObserver ;
  • loadModule(name) résout un module valide et mutualise son import.

Les modules exposant pause et resume sont suspendus hors écran. Lorsqu’un élément hydraté est retiré du DOM, ses observers, media queries et fonctions de nettoyage sont libérés.

Robustesse
  • un nom de module invalide ou un import impossible est journalisé sans interrompre la page ;
  • sans IntersectionObserver, le chargement visible devient immédiat ;
  • un élément supprimé pendant un import asynchrone n’est pas initialisé après coup ;
  • chaque module reste limité à sa racine et doit nettoyer ses propres listeners, timers et RAF.
Réutilisation d’une racine

Après modification de data-module, appeler hydrateElement(root) : l’ancien module est détruit et ses imports en attente sont invalidés. observe() ne surveille que les ajouts et retraits du DOM, pas les mutations d’attributs. La condition média est revérifiée après l’import, avant toute initialisation. Si elle est devenue fausse, l’attente est réarmée. Elle constitue une condition d’initialisation : une instance déjà chargée reste active après redimensionnement. destroy(root) et destroyAll(container) permettent un nettoyage explicite.

Lenis

Active un défilement fluide global pour la page en chargeant le vendor Lenis à la demande.

Son manifeste utilise "activation": { "pageType": "any" } parce que assets/app.js l’initialise globalement dès que le site possède une page. Les manifestes de pages ne doivent pas le déclarer comme dépendance.

Utilisation
import { initLenis } from "@modules/lenis/lenis";

const lenis = await initLenis();

L’instance créée est exposée dans window.lenis. Une fois prête, le module émet l’événement lenis:ready avec l’instance dans event.detail, ce qui permet aux autres modules de se connecter sans imposer un ordre d’initialisation.

Activation

Lenis n’est activé que si :

  • prefers-reduced-motion n’est pas demandé ;
  • le périphérique possède un pointeur précis ;
  • le vendor peut être chargé.

Dans les autres cas, initLenis() retourne undefined et le scroll natif reste actif.

Configuration

L’instance utilise autoRaf, un lerp de 0.14 et un multiplicateur de molette adapté à Chrome. Le vendor reste isolé dans assets/vendors/lenis et ne doit pas être importé directement par les consommateurs.

Contrat
  • appeler initLenis() au démarrage global du site ;
  • utiliser window.lenis uniquement après son initialisation ou écouter lenis:ready ;
  • conserver un fallback avec le scroll natif ;
  • ne pas forcer le défilement fluide lorsque les animations réduites sont demandées.

Module numberCounter

Anime un ou plusieurs nombres de 0 jusqu'à leur valeur affichée. Le module est indépendant des composants et des strates.

Utilisation
import numberCounter from "@modules/numberCounter/numberCounter";

const lifecycle = numberCounter(
    root.querySelectorAll(".value"),
    { duration: 1600 },
);

Le premier argument accepte un élément ou un itérable d'éléments. Le texte de chaque élément constitue la valeur finale.

Formats acceptés

Le module anime les entiers, les décimales et les valeurs négatives :

1250
1 250
1'250
12,5
-42

Les espaces, espaces insécables et apostrophes utilisés comme séparateurs de milliers sont conservés. Le séparateur décimal et le nombre de décimales sont également conservés. À la fin, le texte original exact est restauré.

Une valeur non numérique est ignorée sans être modifiée.

Options
Option Type Défaut Rôle
duration nombre positif 1600 Durée du comptage en millisecondes.

Une durée absente, non numérique, nulle ou négative utilise la valeur par défaut. La progression emploie une courbe easeOutCubic pour ralentir à l'approche de la valeur finale.

Nettoyage

Le module démarre immédiatement et retourne une fonction de nettoyage compatible avec l'hydrateur :

const destroy = numberCounter(elements);
destroy?.();

Le nettoyage annule la frame éventuelle et restaure les textes originaux. Il est idempotent. L'animation étant courte et jouée une seule fois, elle n'expose pas de méthodes pause ou resume.

Si aucune valeur n'est exploitable ou si prefers-reduced-motion: reduce est actif, le module ne modifie pas le DOM et ne crée aucune frame.

Intégration dans une strate hydratée

Le chargement à l'entrée du viewport reste la responsabilité de la strate :

<section data-module="strates/strate-example" data-context="@visible true">

import numberCounter from "@modules/numberCounter/numberCounter";

export default function initExample(root) {
    return numberCounter(root.querySelectorAll(".value"));
}

La strate retourne directement la fonction de nettoyage afin que l'hydrateur puisse détruire proprement le compteur.

Module ScrollDriver

Moteur léger d'animations pilotées par le scroll, sans GSAP. Il centralise les mesures, l'IntersectionObserver, le listener de scroll et le requestAnimationFrame pour tous ses consommateurs.

Lire ce README avant d'ajouter une animation ou de modifier son cycle de vie.

API publique
import {
    ScrollDriver,
    scrollAnimation,
    stagger,
    style,
} from "@modules/scrollDriver/scrollDriver";
Export Rôle
ScrollDriver() Retourne le singleton partagé de la page
scrollAnimation() Crée un lifecycle hydratable { pause, resume, destroy }
stagger(root, progress, options) Distribue une progression sur des enfants avec des variables CSS
style.var() Écrit une variable CSS en évitant les écritures identiques
style.clear() Retire les variables écrites par style et réinitialise le cache de stagger

Les anciennes API SectionAnimate, snap, cubicBezier, upDown, timelineInOut, toggle, trigger et les writers de styles génériques ont été retirés. Ne pas les réintroduire sans consommateur réel.

Utilisation recommandée dans une strate
import {
    scrollAnimation,
    style,
} from "@modules/scrollDriver/scrollDriver";

export default function initStrateExample(root) {
    return scrollAnimation(root, {
        range: [85, 40],
        update(event) {
            event.timeline(0, 100, progress => {
                style.var(root, progress, "--progress");
            });
        },
    });
}

Le helper inscrit immédiatement la strate et retourne le contrat attendu par hydrate. Hors écran, pause() la retire du driver. À son retour, resume() la réinscrit sans doublon. destroy() la retire définitivement et appelle automatiquement style.clear(root), puis le nettoyage spécifique fourni une seule fois.

Lorsque prefers-reduced-motion: reduce est actif, le helper retourne undefined sans inscrire l'élément dans le driver. Les modules qui modifient le DOM avant d'appeler scrollAnimation() doivent toutefois vérifier cette préférence avant leur propre initialisation.

Options :

Clé Type Défaut Rôle
range `string [number, number]` "top-bottom"
update function — Callback reçu par driver.add() ; obligatoire
destroy function undefined Nettoyage spécifique exécuté après le nettoyage automatique des variables CSS

Une cible invalide ou un callback update absent retourne undefined sans activer le driver.

Utilisation bas niveau
const driver = ScrollDriver();

driver.add(section, [85, 40], event => {
    event.timeline(0, 100, progress => {
        // progress est compris entre 0 et 1.
    });
});

driver.enable();

return () => driver.remove(section);

Toujours appeler remove() dans le nettoyage du module propriétaire. Ne pas appeler destroy() depuis un composant : le singleton peut être partagé avec d'autres éléments de la page.

Préférer scrollAnimation() dans une strate hydratée. L'API bas niveau reste utile aux modules ayant plusieurs animations ou un cycle particulier, comme le footer.

Cycle de vie du singleton
driver.add(element, type, animation)

Enregistre un élément et retourne son contrôleur interne. L'appel est ignoré si le driver est détruit ou si la cible n'est pas un élément DOM.

Une cible ne peut avoir qu'une inscription : un nouvel add() sur le même élément remplace proprement la précédente.

driver.add(element, "bottom-bottom", event => {
    event.timeline(80, 100, progress => {
        // progression 0..1 sur la fin de la plage.
    });
});
driver.enable()

Active le driver de manière idempotente :

  • mesure toutes les sections et applique leur état initial ;
  • ajoute le listener resize ;
  • utilise le bridge Lenis partagé lorsque window.lenis existe ;
  • utilise temporairement le scroll natif sinon ;
  • bascule automatiquement vers Lenis lors de l'événement lenis:ready.
driver.remove(element)

Désobserve l'élément, retire .viewed, supprime ses références et appelle release(). Quand la dernière section disparaît, le driver est désactivé :

  • listeners scroll, resize et lenis:ready retirés ;
  • listener Lenis retiré de l'instance exacte qui l'avait reçu ;
  • RAF en attente annulé.

Le singleton vide reste réutilisable.

driver.refresh()

Remesure toutes les sections et réapplique immédiatement leur état au scroll courant. À appeler après un changement de layout qui ne déclenche pas de resize, par exemple après l'ouverture d'un panneau ou l'injection d'un média.

driver.refresh();
driver.disable() et driver.destroy()

disable() suspend les listeners sans supprimer les sections. Un prochain enable() les remesure et les réactive.

destroy() est réservé au teardown global : il désactive le driver, déconnecte son observer et vide toutes ses sections. Le prochain appel à ScrollDriver() créera une nouvelle instance.

driver.onScroll(scrollY)

Planifie une mise à jour avec une position explicite. Cette méthode sert au bridge Lenis ; les composants n'ont normalement pas à l'appeler. Elle ne fait rien lorsque le driver est désactivé ou détruit.

Sections actives et performance

Chaque section est observée avec une marge de 100px. Après l'état initial, seules les sections proches du viewport sont recalculées pendant le scroll. Quand aucune section n'est active, aucun callback d'animation n'est exécuté.

Le driver utilise un RAF partagé et fusionne les événements reçus pendant une même frame. Un resize force une mesure et une mise à jour de toutes les sections sur la frame suivante. Plusieurs événements resize reçus avant cette frame ne provoquent qu'une seule série de mesures.

Types de progression

Le deuxième argument de add() détermine le calcul de event._percent :

Type Plage équivalente Usage
"top-bottom" [0, 100] Type par défaut
"top-top" [0, 0] Du haut de l'élément au bas de l'élément, alignés en haut
"middle-middle" [50, 50] Traversée du milieu du viewport
"bottom-bottom" [100, 100] Traversée du bas du viewport
"middle-bottom" [50, 100] Du milieu vers le bas du viewport
"bottom-top" [100, 0] Traversée complète du viewport
[start, end] — Positions personnalisées du viewport en pourcentage

Les presets sont uniquement des alias lisibles. Tous passent par la même formule générique que les tableaux.

Exemple [85, 40] : la plage commence lorsque le haut de l'élément atteint environ 85% du viewport et se termine lorsque son bas atteint 40%.

API du callback event
event.timeline(start, end, callback)

Découpe la progression de la section entre start et end. La valeur passée au callback est toujours comprise entre 0 et 1.

event.timeline(20, 80, progress => {
    element.style.opacity = String(progress);
});

Plusieurs timelines peuvent être appelées dans le même update. Le contrôle des limites est calculé une fois par mise à jour : toutes reçoivent donc leur valeur finale 0 ou 1 lorsque la section quitte sa plage.

stagger()
stagger(root, progress, {
    selector: ".char",
    softness: 6,
});

progress accepte 0..1 ou 0..100. Pour un élément racine, les enfants sont mis en cache avec leurs racines et leurs options. Les index, le dénominateur et la souplesse sont préparés une seule fois ; pendant le scroll, seule la progression est recalculée et écrite sur la racine :

Variable Cible Rôle
--p Racine Progression normalisée 0..1
--denom Racine Nombre de segments
--softness Racine si fournie Souplesse de la propagation
--i Chaque enfant Index écrit une seule fois

Sélecteur par défaut : [data-progress-item], .char, .item.

Préférer une racine DOM à un tableau d'éléments. Une racine produit des écritures O(1) par frame ; un tableau sans racine commune écrit les variables sur chaque élément.

Nettoyage de stagger
style.clear(root);

Cela retire les variables suivies sur la racine et ses descendants concernés, puis invalide les caches pour permettre une future réinitialisation.

Scroll Top

Replace la page en haut lorsque le site démarre ou lorsqu’une page revient depuis le cache du navigateur.

Utilisation
import initScrollTop, { scrollToTop } from "@modules/scrollTop/scrollTop";

const reset = initScrollTop();

scrollToTop() utilise window.lenis.scrollTo() lorsque Lenis est disponible, puis retombe sur window.scrollTo() avec un déplacement immédiat.

Comportement

À l’initialisation, le module :

  • désactive la restauration automatique du scroll lorsqu’elle est disponible ;
  • replace immédiatement la page en haut ;
  • recommence après load, sauf si l’URL contient une ancre ;
  • recommence après un retour depuis le back-forward cache (pageshow.persisted).

La fonction retournée par initScrollTop() permet de demander manuellement un retour en haut.

Limites

Ce module impose une position initiale en haut et ne convient donc pas à un site qui souhaite restaurer la position précédente après navigation. Les ancres présentes au chargement restent prioritaires lors de l’événement load.

Module splitText

Découpe les nœuds texte d'un élément en spans de mots et de caractères afin de permettre des animations individuelles, tout en conservant le HTML inline.

Dans le catalogue Forge, l'ajout de ce module active également scrollDriver. L'ajout de scrollDriver seul n'active pas splitText.

Utilisation
import { splitText } from "@modules/splitText/splitText";

const { words, chars, restore } = splitText(title);

chars.forEach((char, index) => {
    char.style.setProperty("--i", index);
});

restore();

Structure produite :

<span class="word">
    <span class="char">T</span>
    <span class="char">e</span>
    <span class="char">x</span>
    <span class="char">t</span>
    <span class="char">e</span>
</span>
Options
Option Défaut Description
wordClass word Classe du span enveloppant un mot
charClass char Classe de chaque graphème
skipSelector chaîne vide Ignore les nœuds texte placés dans un élément correspondant

Une classe vide ou invalide reprend sa valeur par défaut. Un sélecteur CSS invalide est ignoré sans interrompre l'initialisation.

Contrat
  • le HTML inline et les éléments existants restent en place ;
  • les listeners et références des descendants sont préservés ;
  • les espaces originaux sont conservés sous forme de nœuds texte ;
  • les caractères Unicode complexes utilisent Intl.Segmenter lorsqu'il est disponible, avec Array.from() comme fallback ;
  • un <br> produit un espace dans le libellé accessible ;
  • un aria-label existant est conservé puis restauré à l'identique ;
  • un second split restaure d'abord le précédent afin d'éviter les spans imbriqués ;
  • restore() est idempotente et retire uniquement les nœuds générés par le split concerné ;
  • une cible invalide retourne des tableaux vides et un nettoyage sans effet.
Nettoyage

Toujours appeler ou retourner restore() lorsque le composant est détruit :

export default function initExample(root) {
    const title = root.querySelector(".title");
    if (!title) return;

    const { restore } = splitText(title);
    return restore;
}

Les modules textAppear et scrollDriver/textAnimated appliquent déjà ce nettoyage dans leur cycle de vie.

textAppear.js

Animation d’entrée de texte (split chars). Indépendant de scrollDriver.

Dépend de splitText pour découper chaque bloc en mots et graphèmes sans reconstruire son HTML inline.

Ajoute text-appear-root, puis is-animated sur root pour déclencher les animations CSS sans dépendre d'une classe active globale non scopée.

Retourne une fonction destroy (idempotente) compatible avec hydrate.

Concept
Étape Comportement
Init Normalise les items, optionnellement attend le viewport (whenVisible)
Split splitText par bloc → .word / .char + vars CSS
Play Double requestAnimationFrame puis is-animated sur root
Destroy Annule rAF / IO et restaure le DOM, les classes et les styles inline d'origine

Le double rAF garantit que l’état initial (opacité 0, translate) est peint avant le déclenchement CSS — évite les flashs sur reveal.

Types
type Effet CSS
reveal Slide up depuis le bas translate: 0 110% → 0
fadein Opacité 0 → 1 pas de translate
Markup attendu
<header class="hero hero-homepage">
    <p class="eyebrow">…</p>
    <h1 class="title">…</h1>
    <p class="intro">…</p>
</header>

Les sélecteurs dans items[].el sont résolus dans root (section, hero, strate…).

Usage — hero (init direct)

Animation immédiate au chargement (whenVisible par défaut false).

import textAppear from "@modules/textAppear/textAppear";

const ITEMS = [
    { el: ".eyebrow", type: "reveal", delay: 0, skipSelector: ".icon", duration: 400, stagger: 18 },
    { el: ".title", type: "reveal", delay: 250, duration: 550, stagger: 24 },
    { el: ".intro", type: "fadein", delay: 450, duration: 220, stagger: 10 },
];

export default el => {
    if (!el) return;

    return textAppear(el, { items: ITEMS });
};
Usage — strate (data-module + hydrate)
<section data-module="strates/strate-example" data-context="@visible true">
Strate seule

Retourner destroy directement :

import textAppear from "@modules/textAppear/textAppear";

export default el => textAppear(el, {
    whenVisible: true,
    items: [
        { el: ".title", type: "reveal", delay: 0, duration: 550, stagger: 24 },
    ],
});
Strate + scroll / listeners

Chaîner le destroy :

const destroyText = textAppear(el, { whenVisible: true, items });

const destroy = () => {
    destroyText?.();
    stepCtrl.destroy();
};

return {
    pause: stepCtrl.pause,
    resume: stepCtrl.resume,
    destroy,
};
whenVisible vs data-context="@visible"
@visible (hydrate) whenVisible (textAppear)
Rôle Lazy-load du module JS Lazy split + play de l’animation
Quand utiliser Strates hors écran au boot Animation déclenchée à l’entrée viewport même si le module est déjà chargé

En pratique : whenVisible: true dans les strates pour ne pas splitter tant que l’utilisateur n’approche pas de la zone.

Options
Option Défaut Description
items [] Blocs à animer
whenVisible false Attendre le viewport avant split + play
rootMargin "100px 0px" Marge IO si whenVisible
threshold 0 Seuil IO si whenVisible
Item
Champ Description
el / node / selector Sélecteur ou élément (relatif à root)
type "fadein" | "reveal"
delay Délai bloc (ms) → --text-appear-delay
duration Durée (ms) → --text-appear-duration
stagger Écart par char (ms) → --text-appear-stagger
skipSelector Nœuds exclus du split (ex. .icon)

Les durées, délais et staggers invalides ou négatifs sont ignorés. Si plusieurs items ciblent le même élément, seul le premier est conservé. Les éléments DOM fournis directement doivent appartenir à root.

CSS
@import "modules/textAppear/textAppear";

Classes par bloc : text-appear, text-appear--fadein, text-appear--reveal.

Animations actives quand le parent possède à la fois text-appear-root et is-animated.

Le module respecte toujours prefers-reduced-motion et ne splitte pas le texte dans ce mode. Le SCSS conserve également un fallback de sécurité.

Robustesse et nettoyage
  • une cible, une option, un item ou un sélecteur invalide est ignoré ;
  • sans IntersectionObserver, whenVisible démarre immédiatement ;
  • le callback visible déconnecte l'observer avant le split ;
  • les classes et variables CSS présentes avant l'initialisation sont restaurées avec leur valeur et leur priorité d'origine ;
  • le nettoyage est idempotent, y compris sans item ou en mode animations réduites ;
  • une erreur d'initialisation restaure les blocs déjà traités et laisse le contenu visible.
Performance
  • whenVisible: true : le split DOM (coûteux) est différé jusqu’à l’IO
  • Double rAF : un seul batch par instance, pas de reflow en boucle
  • destroy idempotent : safe si hydrate rappelle ou PJAX
  • Pas de ScrollDriver : zéro listener scroll pour ce module
  • prefers-reduced-motion : early exit avant split (JS + CSS)
  • Après lecture : les spans restent dans le DOM sans RAF ni listener actif jusqu'au destroy
