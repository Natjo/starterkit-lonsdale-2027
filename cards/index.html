Card card-expertise

Affiche une expertise avec un titre et un texte.

Appel
card('expertise', [
    'title' => 'Conseil stratégique',
    'text' => '<p>Nous accompagnons les transformations de marque.</p>',
]);
Payload
Clé Type Défaut Rôle
title scalar|Stringable '' Titre obligatoire rendu en h3
text scalar|Stringable '' Texte éditorial facultatif

Une card sans titre ne produit aucun HTML. Le texte accepte le HTML éditorial autorisé par le composant text.

Dépendances
  • component('title', [...]) ;
  • component('text', [...]).
Champs ACF

Le groupe Card - expertises est affecté au CPT expertise. Ses champs sont regroupés sous card : card.text (Description) et card.images.desktop / card.images.mobile (IDs). Le préparateur commun les lit directement, sans mapping de clés racine. Le titre, l’extrait et l’image WordPress restent les replis. Les clés des champs ACF existants sont conservées ; seul leur chemin est imbriqué. Les payloads explicites du template restent plats (title, text, image).

Les nouvelles contributions disposent de valeurs de démonstration ; voir le contrat des valeurs par défaut.

Card card-keynumber

Affiche un chiffre clé avec un suffixe, un titre et un texte facultatifs.

Appel
card('keynumber', [
    'value' => '98',
    'prefix' => '+',
    'suffix' => '%',
    'title' => 'de satisfaction',
    'text' => '<p>Mesurée auprès de nos clients.</p>',
]);
Payload
Clé Type Défaut Rôle
value scalar|Stringable '' Valeur visible obligatoire
prefix scalar|Stringable '' Signe ou texte placé avant la valeur
suffix scalar|Stringable '' Unité ou suffixe facultatif
title scalar|Stringable '' Titre rendu en h3
text scalar|Stringable '' Texte éditorial facultatif

Une valeur vide ne produit aucun balisage. prefix, value et suffix sont échappés comme du texte ; title et text délèguent leur filtrage aux composants correspondants.

Cette card utilise normalement un payload personnalisé venant du répéteur ACF de strate-keynumbers. Elle n’attend aucun post WordPress.

Groupe ACF réutilisable

Card - keynumber contient un groupe card avec value (obligatoire), prefix, suffix, title et text (WYSIWYG Basic). Il n’a pas de règle de localisation : aucun CPT Keynumber n’est créé. On peut cloner ce groupe dans un répéteur ACF ; la card et la strate Keynumbers acceptent alors les lignes imbriquées ['card' => ['value' => '98', ...]]. Le clone doit conserver le nom card sans préfixer les noms de champs. Les anciens payloads plats restent acceptés et les champs existants de la strate ne sont pas modifiés.

Les nouvelles contributions disposent de valeurs de démonstration ; voir le contrat des valeurs par défaut.

Card card-news

Affiche une actualité. Cette card est rendue avec card() et non avec component().

Le manifeste card-news.json décrit les champs de contribution consommés par WP Forge. Il doit rester synchronisé avec le payload documenté ci-dessous.

Utilisation recommandée
Depuis un post WordPress
card('news', 123);

123 doit être un entier strictement positif. Le dispatcher charge les champs ACF du post, ajoute post_id, puis les transmet à la card.

Depuis un contenu personnalisé
card('news', [
    'date' => '22 juillet 2026',
    'datetime' => '2026-07-22',
    'title' => 'Titre de l’actualité',
    'text' => '<p>Résumé de l’actualité.</p>',
    'image' => 123,
    'image_size' => 'large',
    'link' => [
        'url' => '/actualites/titre/',
        'title' => 'Lire l’actualité',
        'target' => '_blank',
    ],
]);

Le payload doit être un tableau associatif non vide.

Depuis un post avec des surcharges
card('news', [
    'post_id' => 123,
    'title' => 'Titre remplacé pour ce rendu',
]);

Les champs ACF sont chargés en premier. Les valeurs fournies dans le tableau les remplacent.

Payload
Clé Type Défaut Rôle
post_id int aucun ID du post source, ajouté par card()
date scalar|Stringable '' Date visible
datetime scalar|Stringable '' Date machine au format HTML datetime
title scalar|Stringable '' Titre rendu en h3 avec la classe title-3
text scalar|Stringable '' Résumé acceptant du HTML éditorial filtré
image ID|URL aucun Image principale rendue en mode cover
image_size string|array{int,int} large Taille transmise à picture
link array [] Lien de la card
Structure de link
'link' => [
    'url' => '/destination/',
    'title' => 'Libellé descriptif',
    'target' => '_blank',
],

Comportement actuel du template :

  • link.url décide si .card-content est un lien <a> ou un <div> ;
  • link.title n’est pas affiché ;
  • link.target est appliqué lorsqu’il est fourni ;
  • _blank ajoute rel="noopener noreferrer".
Champs ACF attendus

Pour un appel par ID, les données sont normalisées par theme_post_card_item() : groupe ACF card, mapping métier du CPT, puis valeurs WordPress.

Le groupe Card - news contient un groupe ACF card. Ses champs card.text et card.images.desktop / card.images.mobile sont lus directement par le préparateur commun, dans le hub et tous les autres listings. Aucun mapping de champs racine n’est nécessaire. Une description vide laisse le repli sur l’extrait WordPress.

Les payloads explicites utilisent directement text. post_id est fourni automatiquement et ne nécessite aucun champ ACF.

Dans une liste
component('list', [
    'items' => [123, 456],
    'card' => 'news',
]);

Les items peuvent aussi être des payloads personnalisés ou mélanger les deux formes.

Dans un slider
component('slider', [
    'items' => [
        123,
        ['title' => 'Actualité personnalisée', 'text' => '<p>Résumé.</p>'],
    ],
    'card' => 'news',
]);
Règles importantes
  • Utiliser card('news', ...) ou card('card-news', ...).
  • Ne pas utiliser component('card-news', ...).
  • Un ID nul, négatif ou fourni sous forme de chaîne est refusé.
  • Un tableau vide ou positionnel est refusé par le dispatcher.
  • Le template produit actuellement son <article> même si toutes les valeurs du payload sont vides.
  • Les classes et attributs personnalisés de l’élément <article> ne font pas partie du contrat actuel.
Images responsive

Le groupe Images de Card - news fournit card.images.desktop et card.images.mobile (IDs). Les deux variantes sont transmises au composant picture. Sans image de card, l’image mise en avant sert de repli. Le payload explicite image reste accepté ; images explicite est prioritaire.

Si aucune source n’est fournie (y compris deux variantes vides), la card affiche assets/img/placeholder.svg en cover, avec un texte alternatif vide : cette image de remplacement est décorative. Une variante mobile seule reste utilisée.

Les nouvelles contributions disposent de valeurs de démonstration ; voir le contrat des valeurs par défaut.

Card card-page

Affiche un résultat de page ou le fallback d’un type de contenu ne possédant pas de card dédiée.

Appel
card('page', [
    'post_id' => 123,
    'type' => 'Page',
    'title' => 'À propos',
    'text' => '<p>Présentation facultative.</p>',
    'link' => [
        'url' => '/a-propos/',
        'title' => 'Voir la page',
    ],
]);
Payload
Clé Type Défaut Rôle
post_id int aucun Identifiant facultatif du contenu source
type scalar|Stringable '' Type de contenu affiché en surtitre
title scalar|Stringable '' Titre obligatoire rendu en h3
text scalar|Stringable '' Résumé éditorial facultatif
link array [] URL, libellé et cible facultative

Une card sans titre ne produit aucun HTML. Une URL absente remplace le lien par un <div>. La cible _blank ajoute rel="noopener noreferrer".

La page de recherche construit explicitement ce payload depuis WordPress. Les enrichissements ACF propres à un CPT passent par le filtre theme_search_result_item déclaré dans inc/config/search.php. La card ne lit aucun groupe ACF implicitement.

Dépendances
  • component('eyebrow', [...]) ;
  • component('title', [...]) ;
  • component('text', [...]).
Contribution ACF

Le groupe Card - page s’affiche dans le BO des pages WordPress. Il contient card.title (titre facultatif) et card.text (description WYSIWYG Basic). Ces valeurs sont utilisées par le préparateur commun dans les recherches et les remontées de pages. Sans titre de card, le titre WordPress est conservé ; sans description, l’extrait sert de repli. Le lien reste le permalien de la page. Ce groupe est distinct des champs du hero et du contenu de la page.

Les nouvelles contributions disposent de valeurs de démonstration ; voir le contrat des valeurs par défaut.

Card card-slide

Card éditoriale utilisée par slider-cards, sans publication WordPress.

Le manifeste définit designSystem.columns: 2 pour ouvrir la démonstration sur deux colonnes. Ce réglage ne modifie pas la grille du site.

card('slide', [
    'title' => 'Notre engagement',
    'text' => '<p>Une description courte.</p>',
    'image' => 123,
    'link' => ['url' => '/engagement/', 'title' => 'Découvrir'],
]);

title, text, image et link sont facultatifs, mais la strate ignore une ligne où les trois contenus visibles sont vides. Un lien valide transforme la card en lien ; sans URL, elle conserve un conteneur non interactif. L’image ACF est attendue sous forme d’identifiant WordPress.

Le texte est limité visuellement à trois lignes, avec des points de suspension en cas de dépassement. Le contenu HTML complet reste présent dans la page.

Groupe ACF réutilisable

Card - slide regroupe card.title (texte), card.text (WYSIWYG Basic), card.image (ID) et card.link (tableau ACF). Tous les champs sont facultatifs. Le groupe n’a pas de règle de localisation et ne crée aucun CPT : il peut être cloné dans un répéteur, en conservant le nom card sans préfixage des champs. La card et la strate Slider Cards acceptent les lignes imbriquées sous card, ainsi que les anciens payloads plats. Les champs actuels de la strate restent inchangés ; une ligne sans titre, texte ni image est toujours ignorée.

Les nouvelles contributions disposent de valeurs de démonstration ; voir le contrat des valeurs par défaut.

Card card-team

Affiche un membre de l’équipe depuis un post WordPress ou un payload.

card('team', [
    'title' => 'Jane Doe',
    'text' => '<p>Creative director</p>',
    'image' => 123,
    'image_size' => 'large',
    'link' => ['url' => '/team/jane-doe/', 'title' => 'Jane Doe'],
]);

link.url transforme le contenu de la card en lien. title, text, image et image_size sont transmis aux composants correspondants.

Contribution WordPress

Le groupe ACF Card - team s’affiche sur les fiches du CPT Team dans le BO.

Tous les champs sont imbriqués dans le groupe ACF card.

Champ Chemin ACF Type
Picture card.image Image, retour ID
Function card.function Texte

Le préparateur commun lit l’image directement et le mapping ['text' => 'card.function'] fournit la fonction au composant texte. Le titre de la publication reste le titre de la card. Les payloads directs continuent d’utiliser title, text et image, sans imbrication imposée.

Les nouvelles contributions disposent de valeurs de démonstration ; voir le contrat des valeurs par défaut. Le portrait par défaut déclaré pour Forge est assets/img/placeholders/card-team-1.png. Les autres portraits card-team-2.png, card-team-3.png et card-team-4.png restent disponibles pour varier les contenus. Le Design System utilise les trois premiers pour ses exemples. Les images déjà contribuées ne sont pas remplacées.

Card card-testimonial

Affiche un témoignage en s’appuyant sur le composant quote.

card('testimonial', [
    'quote' => '<p>Une collaboration remarquable.</p>',
    'image' => 123,
    'image_size' => 'full',
    'author' => 'Jane Doe',
    'source' => 'Example Company',
]);

quote est obligatoire. La card transmet l’image, l’auteur et la source au composant quote. La source est toujours rendue comme du texte, sans lien. Le composant filtre le HTML de la citation et échappe les libellés.

Contribution ACF

Le groupe Card - testimonial apparaît sur les fiches du CPT Testimonial. Ses champs sont imbriqués dans card :

Champ Chemin Type
Citation card.quote WYSIWYG Basic, obligatoire
Portrait card.image Image, retour ID
Auteur card.author Texte
Source card.source Texte

La card accepte le groupe imbriqué et les payloads plats existants. Un témoignage publié peut être rendu par ID même si son CPT n’expose pas de single ou d’archive. Les statuts privés, brouillons et les contenus protégés restent exclus. Aucun contenu de démonstration n’est enregistré automatiquement.

Les nouvelles contributions disposent de valeurs de démonstration ; voir le contrat des valeurs par défaut.
